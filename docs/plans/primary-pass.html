aurora primary pass

Split the camera-ray chain out of the path-tracing raygen into a slim primary pass, run ReSTIR DI between the two, and let the path tracer resume sample 0 from the stored hit and shade the ReSTIR winner itself. Written 2026-10-14. Implementation notes: primary-pass-notes.md.

Status 2026-10-15: phases 0–3 done (the old frame and restir_shade are deleted); phase 4 open. Results, deviations and what is untested are in the notes.

Why. Northshire bench, 3840x1080 Balanced (GPU Trace, aurora 0533cc0): restir_shade is a whole raygen dispatch (0.32 ms) that exists only because ReSTIR's reservoirs are ready after the trace. The trace itself is L2-bound (78 % of L2 throughput, 54 % L1 hits) with instruction-cache stalls (no_instruction 8 %): its code is the whole camera chain plus the path, and its live state (544 B stack) spills through L1/L2. The camera chain (alpha pass-through, portals, glass deferral, DLSS guides, the spec-hit probe, the camera ray's fog, the exposure meter) runs once per pixel and is not path tracing.

today:   fog grid → restir grid → trace (camera chain + path, writes surfaces) → restir temporal → restir spatial → restir_shade (shadow ray, += colour)
planned: fog grid → restir grid → primary (camera chain, guides, surfaces, hit record) → restir temporal → restir spatial → trace (resumes, shades the winner)

Everything the camera chain decides randomly (pass-through coins, which portal) is decided once, in the primary pass; the path tracer never re-rolls it.

D2. The primary-hit record (data model)

// One per traced pixel, written by `primary`, read by `main` (sample 0). 64 bytes, aligned.
public struct PrimaryHit {
    public float3 origin;        // the last segment's start (after pass-through / portals)
    public uint   state;         // kind (2 bits) | bounces used (6) | ray_mask (8) | environment (3)
    public float3 direction;     // that segment's direction (full float: the hit is rebuilt from the ray)
    public float  t;             // hit distance along it
    public uint   instance;      // TLAS instance index (HitObject.GetInstanceIndex)
    public uint   geometry;      // geometry index within the BLAS
    public uint   primitive;     // primitive index
    public uint   bary;          // barycentrics, 2x unorm16
    public float  cone_width;    // the ray cone's width at the hit
    public float  meter_albedo;  // the exposure meter's divisor (< 0 = not metered)
    public float  primary_t;     // first hit distance (0 = sky), for the atmosphere composite
    public uint   hit_kind;      // front / back face
};
// kind: 0 RETRACE (main traces from the camera as today, guides and camera fog already done)
//       1 HIT     (main rebuilds the hit with HitObject::MakeHit and Invokes its closest hit)
//       2 ENDED   (sky or emitter: origin.xyz holds the radiance, main adds it and stops)
  • Lives per view at trace resolution beside the ReSTIR buffers (restir.rs owns allocation, or a small primary.rs); its address goes to the RT push constants.
  • RETRACE is the conservative escape: procedural spheres (their attributes are not a barycentric pair), fog in random-scatter mode (Fog::steps == 0: the camera segment itself may scatter), and anything else that turns up (logged in the notes).
  • Traffic: 64 B written + read per pixel, about 180 MB per frame at 1.4 MP, roughly 0.1 ms. The 64 B surface record is unchanged (now written by primary).

D3. Resume by MakeHit + Invoke, not by re-tracing (mechanism)

The path tracer rebuilds sample 0's hit from the record with SER (HitObject::MakeHit → OpHitObjectRecordHitNV, verified with slangc 2026.8), reorders on it, and runs the hit's closest-hit shader into its payload. No traversal is repeated; the closest hit sees the same WorldRayOrigin, RayTCurrent, instance and barycentrics it saw in the primary pass, so the payload is identical.

Alternative: the primary pass stores the whole 23-word payload instead. Rejected: twice the record, and the material work is cheap next to the extra traffic.

D4. Guides follow the dominant lobe through smooth glass (behaviour change)

Today guides behind smooth glass are written by whichever path continues: when that path rolls the minority Fresnel lobe, the frame keeps last frame's guides (PATH_GUIDE_LIVE). The primary pass instead follows the dominant lobe deterministically (refract or reflect, whichever Fresnel favours) through up to 4 smooth-transmission vertices and writes the guides at the virtual point, every frame (RTXPT's stable planes). The radiance path keeps its own random lobe choice.

Effect: no frames with stale guides behind glass. If you prefer the exact old behaviour, the conservative option is: primary writes no guides for glass pixels and RR keeps last frame's (what happens on a minority roll today).

D5. Samples > 1 (rendering)

Only sample 0 resumes. Samples 1.. trace from the camera in main as plain paths (no guides, no camera fog: the fog veil comes from sample 0 alone instead of their average). The default is 1 sample per pixel, so this only matters for the accumulation / reference modes.

D6. How the path tracer shades the ReSTIR winner (quality vs. rays)

At its first vertex (sample 0), main reads the final reservoir and evaluates the exact contribution (layered BSDF, MIS weight) times W, exactly as restir_shade does.

  • (a) Own shadow ray (default): one traceVisible for the winner, as today, but inside the path tracer. Same quality; the pass, its launch and its read-modify-write of the colour image go away.
  • (b) Shared shadow ray: propose the winner into the vertex's ShadowPick beside the sun, sky and table NEE, one ray for all. Saves a ray per pixel but makes the ReSTIR term stochastic (more noise where lamps dominate: the abbey interior). Measured with --ab and judged inside the abbey before adopting.

D7. Rollout, settings and what is user-facing (settings)

  • Nothing new in RenderSettings or the F3 panel when done. During the work, RenderSettings::ab selects the old frame (0) or the new one (1) on both sides (the view lane's dispatch order and the shaders), so every phase is measured in one run with zero's bench --ab; the old path is deleted at the end with the ab branches.
  • The primary raygen joins the main RT pipeline (one more raygen record, like fog_grid) and shares its register allocation for now. Its own pipeline is phase 4 (needs a second hit-group table in the SBT).
  • Debug views keep working: they read the guides, which the primary pass writes.

Risks

  • MakeHit fidelity. Instance index vs. custom index, the SBT offset (0 / stride 0, as trace), hit kind and skinned meshes (instance rows are per frame, the record is used the same frame). Phase 0 exists to prove the payload is bit-identical before anything else moves.
  • RNG streams. The primary pass and the path tracer draw from different streams; sample 0's path is statistically the same, not the same sequence. Shots compare by ratio, block error and boil, which is how every change today was judged.
  • XR. Two eyes = two views: two primary passes, two records, as with the ReSTIR buffers. Test XR after phase 2.
