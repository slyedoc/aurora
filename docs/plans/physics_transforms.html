Physics on GPU Transforms

avian rides aurora's GPU transform hierarchy: one owner per pose, work proportional to what moved, a static world free. Plan for the aurora + avian fork change (2026-10-20).

Why. The whole Eastern Kingdoms (687 tiles, ~150k static colliders) runs a 139 ms CPU frame, 113 ms of it avian: propagate_collider_transforms (10.6 ms) and the fork's transform_to_position (4.7 ms) walk every collider's hierarchy on every fixed step, six steps a frame (the catch-up spiral). Nothing in that world moves. aurora already propagates every Transform on the GPU and knows exactly what changed; avian redoes it on the CPU, and its own bodies' poses make a full round trip back to it.

1. Decisions to review

D1. Who owns a pose

Every collider or body pose has exactly one source, and only that source does work for it.

OwnerWhoHow avian learns the poseCost
avianDynamic bodies; kinematic bodies driven by velocity It wrote it. Never read back.per awake body
gameplayNon-static bodies moved by writing Transform in the fixed step: the KCC (bevy_ahoy writes Transform), teleports Same step: a Changed<Transform> check over non-static bodies only (an archetype filter, so the scan is over a few hundred entities, never the world)per non-static body
hierarchyColliders that moved because an ancestor moved: a door under a swinging frame, a tile dragged in jackdawThe change list (D2), next frameper moved collider
nobodyStatics: nearly the whole mapComposed once when added (an observer) zero after spawn

Ownership is derived, never authored: no component to remember. Static = RigidBody::Static or a collider with no body; avian-owned = Dynamic, or Kinematic with no Transform write that step.

D2. Where the "what moved" list comes from

recommended(b) CPU seeds from aurora's extract. aurora's extract_transforms already finds every entity whose Transform or parent changed this frame (the seeds it uploads), once per frame. It publishes them as a list. avian expands each seed down only through children that carry its own AncestorMarker<ColliderMarker> / ColliderMarker, recomposing those colliders in f64. That stops at PhysicsEnvironments and at bodies avian owns.

  • Precise: f64 compose, environment-relative, as now.
  • Environment-aware: a moving environment (a planet, a ship) changes no Position inside it, so its seed is skipped. A GPU world-pose list would flood with its whole subtree every frame.
  • Works with no render device (headless server, tests).
  • Bones and meshes never enter it: the descent only follows collider markers.

alternative(a) The GPU readback set. The slots propagate rewrote are already copied back. That's free to publish, but they are world-space f32 poses: precision is lost, it includes every animated bone, and it floods under moving environments. A GPU-side compaction (a "physics node" flag and a second list that stops at environment nodes) fixes the last two, not precision.

Either way the readback stays as it is: it is what feeds GlobalTransform.

D3. Where the bridge lives

recommendedThe avian fork gets a generic "external transforms" mode; aurora implements it (a new src/physics_pose.rs). aurora already adds avian's PhysicsPlugins in AuroraDefaultPlugins and makes baked collision into avian colliders, so no new crate. avian's side has no aurora types in it, so it stays rebasable on upstream and could be proposed there.

alternativeA separate aurora_avian crate. Only worth it if aurora ever wants a physics-free build.

D4. Transform on avian-owned bodies

recommended firstKeep mirroring it, but only for bodies avian moved this step (its own write list, not a Changed<Position> scan). All gameplay code that reads a body's Transform keeps working: the camera follows the rig's Transform, as do NPC and story code. The GPU upload stays aurora's ordinary extract path. Interpolation is unchanged: it eases the mirror.

end state, P4avian writes the world pose straight into the body's GPU node through a frame override: the node composes against its environment's node rather than its ChildOf parent, with its local = Position/Rotation. That removes the inverse chain walk (position_to_transform's frame_chain) and the one-frame-stale parent it converts against. Transform becomes optional for such bodies (read GlobalTransform or Position). Worth it once a scene has many dynamic bodies under deep hierarchies; measured on the stress scene before committing to it.

D5. Lag, as gameplay sees it

  • Gameplay moves (the KCC, teleports via Transform or Position): physics sees them the same step, as today.
  • Hierarchy moves (an ancestor moved in Update, or in the editor): physics sees them the next fixed step, exactly as today (Update runs after the fixed loop).
  • GlobalTransform: unchanged (last frame's GPU readback).

D6. The fixed-step spiral

With physics nearly free, six catch-up steps stop being a spiral. Still cap them: Time<Virtual> max delta at 3 fixed steps' worth (a slow frame slows the simulation instead of snowballing). recommendedin zero's app setup, not aurora's (it's a game policy).

D7. Upstream CPU mode stays

TransformSync::Cpu stays avian's default and its current behaviour, tests included. aurora switches its worlds to External. That keeps the fork's diff to one mode, not a rewrite of avian's sync.

2. New types and interfaces

avian fork (physics_transform)

/// Who keeps Position / Rotation / ColliderTransform in step with the hierarchy.
pub enum TransformSync {
    /// Walk the hierarchy every step (upstream's behaviour; the default).
    Cpu,
    /// Driven by the host: newly added colliders and bodies compose once (an observer),
    /// non-static bodies are checked for Transform writes each step, and everything else
    /// recomposes only when listed in `HierarchyMoves`.
    External,
}
// New field: PhysicsTransformConfig { sync: TransformSync, .. }

/// Entities whose own Transform or parent changed since the last physics step: the host
/// fills it, avian drains it at the first step after (seeds, not descendants).
#[derive(Resource, Default)]
pub struct HierarchyMoves(pub Vec<Entity>);

/// Bodies whose Position / Rotation avian wrote this step (the solver's awake set plus
/// teleports): what the host mirrors and uploads. Cleared at the start of each step.
#[derive(Resource, Default)]
pub struct PhysicsMoves(pub Vec<Entity>);

aurora (gpu_transform.rs, new physics_pose.rs)

/// Entities extract saw a local or parent change for this frame (the seeds it uploaded).
/// Fed into avian's HierarchyMoves by physics_pose.rs.
#[derive(Resource, Default)]
pub struct TransformSeeds(pub Vec<Entity>);

// P4 only: a node composes against `frame`'s node instead of its ChildOf parent, its local
// being the pose in that frame. physics_pose.rs sets it to the body's PhysicsEnvironment
// for avian-owned bodies and writes Position / Rotation as the local.
#[derive(Component)]
pub struct PoseFrame(pub Entity);

On the GPU (P4): one more column, the frame slot (NO_NODE = use the parent). The propagate kernel's ancestor walk starts from the frame slot when set. Children still list under their ChildOf parent, so frontier expansion is unchanged.

5. Phases

  1. P0 Baseline. Tracy for Northshire and the full map (the full map is done: 139 ms). A stress example (aurora examples/physics_stress.rs, no flags, a feathers panel for the sphere count) dropping N spheres onto a baked scene. It's also the start of the pool test (spheres in water).
  2. P1 External mode, statics free. avian: TransformSync::External, an observer to compose on add, draining HierarchyMoves through collider markers. aurora: TransformSeeds from extract, and physics_pose.rs wiring it, setting External and propagate_before_physics = false. Done when: the full map's physics is under 1 ms while still, and Northshire behaves the same.
  3. P2 Moved bodies. The non-static Changed<Transform> step check (gameplay owner); PhysicsMoves from the solver's writeback; position_to_transform over that list instead of a scan. The fixed-step cap (D6) lands in zero.
  4. P3 Cleanup. Delete the fork's every-step compose path under External; one compose function shared by the add observer, hierarchy moves and the Cpu mode; tests for each owner.
  5. P4 Frame override (D4 end state). A GPU frame-slot column, PoseFrame, avian-owned bodies written as environment-relative locals, the mirror optional, interpolation easing the local. Kept only if the stress scene shows it.

6. Mechanical work

avian fork

  • PhysicsTransformConfig.sync; the External branch's systems run instead of transform_to_position and propagate_collider_transforms, chained in the same sets (PhysicsTransformSystems::{Propagate, TransformToPosition}).
  • An add observer (On<Add, Position> plus the ColliderOf insert hook avian already has): compose the entity's environment-relative pose (compose_to_physics_world) and its ColliderTransform relative to its body.
  • Drain HierarchyMoves once per frame (first step after it fills): per seed, depth-first through children matching ShouldPropagate, stopping at PhysicsEnvironment and at non-static bodies; recompose Position/Rotation (rootless colliders) or ColliderTransform (child colliders), with the existing tolerance compare.
  • Non-static check: Query<.., (Changed<Transform>, Without<Static>-equivalent)> using the is_changed_after_tick idiom already there, so avian's own mirror writes don't count.
  • PhysicsMoves filled at the solver's writeback (Position integration for awake bodies) and by teleport handling; position_to_transform iterates it.
  • Tests in physics_transform/tests.rs: a static under a moved parent; a moving environment changes nothing; KCC-style Transform writes the same step; a body's mirror round-trip; add-time composition under a deep chain.

aurora

  • extract_transforms pushes each seed entity into TransformSeeds (it already visits exactly those); cleared each frame.
  • physics_pose.rs: insert PhysicsTransformConfig { sync: External, propagate_before_physics: false, .. } in the plugin group; a First system moving TransformSeeds into HierarchyMoves; registered in AuroraDefaultPlugins beside PhysicsPlugins.
  • P4: PoseFrame column (scatter, the propagate kernel's starting slot in transform.slang), and the writer for avian-owned bodies.

zero

  • The Time<Virtual> max-delta cap in build_app.
  • Re-run the Tracy captures (P0's recipe: --features remote,trace, RUST_LOG=…,bevy_asset::server=warn, tracy-capture -s 110).

Risks

  • A collider whose ancestor chain has a gap with no collider marker would be missed by the descent. avian inserts the markers on every ancestor of a collider, so the descent follows exactly avian's own invariant. A test covers reparenting.
  • Something that moves a static's ancestor inside the fixed step (not Update) is seen a step late. Nothing does this today; it's logged if found.
  • Rebasing the fork: the change sits behind one enum branch and new systems, without rewriting upstream's.
