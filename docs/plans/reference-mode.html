Reference mode and float captures

aurora, 2026-10-15. Notes: reference-mode-notes.md. Base: 17ceb00 (ReSTIR GI frozen).

Why. Every measurement so far went through Ray Reconstruction, a non-linear denoiser that keeps or drops energy depending on how the noise is shaped. So "is the tracer biased?", "does it converge?" and "is this flicker RR's?" cannot be told apart, and every test became a sweep that ended in "it depends". Before ReSTIR PT (and before fixing the sphere's rim, its flickering reflection, or the inexact BSDF pdf) the renderer needs ground truth: the traced image accumulated to convergence with RR out of the loop, captured as linear floats at a fixed size nothing outside the program can change.

Decisions you are most likely to tweak

D1. Accumulation: what, where, when it resets (data model)

A compute pass after gi_shade adds each frame's noisy colour, divided back by the input exposure (so it is radiance in nits, not pre-exposed), into an RGBA32F buffer per view at trace resolution: rgb the running sum, a the frame count. The sub-pixel jitter keeps running, so the reference is antialiased the way the trace is. Nothing else changes: same raygen, same settings, RR still runs on its own input.

It resets (count to 0) when anything that changes the image changes: the camera's view or projection, RenderSettings, the scene (the TLAS rebuilt with moved instances, a material or light change), the trace size, or a DlssReset. When in doubt it resets: a reference that silently mixes two scenes is worse than none.

On only while asked for (D2): the buffer is 16 B/px, ~22 MB at 3840x1080 Balanced.

D2. What you see (user-facing)

AuroraDebugView::Reference (F4, AURORA_DEBUG_VIEW=reference): the accumulated image instead of RR's output, through the same exposure and tonemap (or --raw), upscaled to the output by bilinear filtering, and the frame count in the corner of the dev UI. It is the "RR-off" view: watch it converge, compare it with F4 back to the normal frame.

A second view, ReferenceDiff, shows RR's output against the reference as a signed false colour in stops (blue darker, red brighter): where RR, not the tracer, is wrong.

D3. Captures: format and contents (file format)

PFM (portable float map: a text header and raw little-endian f32 rgb, no dependency to read or write). One capture is a directory with:

filewhat
reference.pfmthe accumulation after N frames (nits), trace resolution
noisy.pfmone frame's noisy colour (nits), trace resolution
noisy-k.pfma few consecutive noisy frames, for the input's own temporal statistics
output.pfm, output-k.pfmRR's output (nits, before exposure and tonemap), output resolution, a few consecutive frames
capture.jsonsettings, camera, sizes, frame counts, exposure

Read back through a staging buffer after the frame's fence, as screenshots are.

D4. Headless, fixed-size runs (how tests run)

The test examples (sun_room, many_lights, later Northshire through zero) take --capture DIR --size WxH --frames N: no window (WindowPlugin without a primary window), one camera rendering into an image target of exactly WxH, the capture written after N accumulated frames, then exit. The compositor cannot resize it and the mouse cannot move it. A shared helper (bevy_aurora::util::capture) does the work so every example and zero get it with a few lines.

Moving tests: --path moves the camera along a scripted path at a fixed rate per frame (frame-locked, not wall-clock), capturing RR's output each frame; the reference for a moving view is the same path accumulated per pose at low speed (later step).

D5. What gets measured (metrics)

scripts/refcmp.py (numpy only) on two capture directories or one:

  • Convergence of the reference itself: halves of the accumulation against each other (so we know the reference is good enough to judge by).
  • Tracer bias: one variant's reference against another's (e.g. GI on vs off, a BSDF change), mean ratio overall and per 16x16 block, in linear nits. No denoiser involved.
  • Input noise: per-pixel variance of the noisy frames around the reference, and how clumped it is (spatial autocorrelation of the residual at 1..32 px) -- the thing that made spatial reuse blotchy, now a number.
  • RR: output against the reference (bias, error) and its frame-to-frame change.

How it will be used first

  1. Sun room and many_lights references at 2048 frames: does the tracer converge, sharp and stable, on the sphere and at its rim? (Answers whether the black rim is the tracer's or RR's.)
  2. GI on vs off references: bias of the GI estimator, without RR.
  3. Per-material furnace-style checks for the BSDF (a uniformly lit sphere per material against its analytic answer), then the exact-pdf BSDF sampler.
